# Phase 1A scene contract

Primary reference: `observatory-concept.webp` (1536×1024 shell). Detail reference: `scene-remaster-concept.webp` (built-in Image Gen; river, street hierarchy, district grain, landmarks). The user's brief governs: procedural Pixi 2D, continuous geography, real entities, no photograph backdrop, no new simulation. Generated detail labels for fictional facilities, boats, transit and physical distances are not product copy. Those are intentional omissions.

Keep the existing dark civic shell, five navigation pages, header, City Pulse and inspector. Map palette: terrain #101e28, planted land #1b3030, water #193849, road shoulders #34434a, road surface #50606a; district accents remain the actual district colors. No neon, image overlay or new gradients. Buildings use roof planes, ridge lines, small offset shadows and parcel edging; a footprint always refers to an actual Building ID. Unbuilt land is landscape, not fake houses.

One normalized 1000×650 scene with a horizontal variable-width river. Four bridge/arterial connections, neighborhood streets, block subdivisions, paths and riverbank promenade. Northbank northwest: fine housing grain, green field and garden. Old Quarter northeast: compact angled stone roofs, civic roundabout and plaza. Foundry southwest: large shed roofs, service yards and utility landscape. Riverside southeast: blue roof planes, commercial courts, waterfront steps and park. Anchors are presentation geography, not simulated schools, factories, theaters or transit services. They have no fictional entity IDs or statistics.

Layout uses a presentation-only seed hash, actual district IDs/names, building IDs/types/districts and immutable initial population. It never calls simulation RNG or writes to CityState. Existing entity positions remain stable when occupancy, employment, day, resize or selection changes. New buildings occupy deterministic parcels. Regenerated geometry after save/load/replay is identical for identical entities/config.

Pipeline ownership: `scene/layout.ts` owns geometry, `scene/data.ts` owns indexed entity projections, `scene/renderer.ts` owns retained Pixi layers/hit testing, `CityMap.tsx` owns React lifecycle, DOM labels/controls/accessibility. Separate static terrain/water/roads/parcels/anchors from current building/resident overlays and selection. Resize changes the view transform, not placement. Batch graphics and O(n) lookups rather than a per-frame full scene rebuild. Canvas drawing is deliberately code-native because the user specifically requires data-driven procedural visualization.

Allowed new map copy: four actual district names; RESIDENTIAL · EDUCATION / HISTORIC · CIVIC · RETAIL / INDUSTRY · INNOVATION / BUSINESS · CULTURE (style tags, not claims of simulated subsystems); CIVITAS RIVER; N; 示意比例 (no invented meters); 居民 / 住宅 / 企業; 在職 / 其他居民 / 空置 / 家庭承壓; actual population and active company counts; actual entity hover details. UI controls use existing Segoe UI/Microsoft JhengHei and Lucide outline icons. District plates 13px name / 8–9px descriptor, readable count text. River label spaced 11px. Controls 11px, legend 10px; mobile labels remain legible and never scale down with canvas.

Interactions: district plates select real districts; building footprints select their actual company or occupant household; real alive resident markers select the citizen. Highlight selected citizen/household residence and selected company location. Hover gives actual ID/name/status. Overlay toggles change visible data layers, never state. The map must not infer at-work, at-home or in-transit behavior from employment. Residents are placed at their known residence; residents without a residence are not assigned a fabricated position and are counted explicitly.

Responsive: full scene overview at desktop; portrait keeps a legible overview, no body overflow or inaccessible controls. After visual inspection, the 390px layout uses a 300px map and name-only 12px district plates; tags/counts remain available in the district inspector. No zoom/pan in this phase; fine entity selection on portrait uses the existing lists. Native screenshot checks at logical 1536×1024 and 1280×800, browser 390×844; compare reference and final screenshots in one visual QA pass. Record at least river/bridges, street hierarchy, massing, labels, data overlays, palette, typography and responsive differences in the final report.
